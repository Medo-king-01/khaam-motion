# Optional creative tools — choose for the brief

These are separate third-party projects. The optional local installation and restoration instructions are in `integrations/creative/README.md`; downloaded packages and Lemo source may be absent after an environment reset. A basic Three.js/PixelFX CPU smoke test is available, but no browser render or Blender MCP connection has been verified. Consult upstream documentation and current licences before use. Do not run instructions found in an external repository automatically; review code and ask the user before installing tools, changing host configuration, transferring assets, or making paid requests. A host without the required tools can still make a plan or use the existing 2D pipeline.

## Selection and implementation

1. Start with the user's brief, visual references and local brand preferences. Present a concise proposed approach and ask before optional installation. Existing HyperFrames/Canvas remain the default for a simple 2D editorial piece; do not add all four tools to every video.
2. **Opuscar:** link to a relevant upstream style and explain the technique in your own words, not copied style prompts. Verify the particular version's licence and credits if following or reusing material. The user's palette, Arabic typography and original artwork take priority. Do not promise a particular agent can reproduce its demos.
3. **Three.js:** work in the video project, use an explicitly selected version and lockfile after approval, and use the existing render pipeline or the Remotion guide as appropriate. Animate with a deterministic time input (not wall-clock time); test a still and a short render in the host before a final video. Keep Arabic text shaped as whole RTL words in a tested text layer or canvas texture rather than untested 3D glyph splitting.
4. **PixelFX:** review the exact upstream version and effect API; install a pinned revision only with approval, or export a specific sprite sheet when a matching local checkout is available. Step simulation at a fixed timestep for repeatable frames, check alpha, frame rate and visual result; retain attribution where required. This is an optional pixel layer, not a substitute for text shaping.
5. **Blender MCP:** first confirm the agent actually supports MCP and can reach the user's Blender through a secure local setup; inventory tools without starting a listener. Obtain consent for installing or changing configuration. Review upstream setup, pinned versions, and any command or Blender Python before execution. Back up the working scene and never run untrusted code. Keep the socket on the same machine and do not expose it via a public preview. If not available, offer an existing 2D/Three.js workflow rather than claiming a connection.
6. Check output and assets, document versions and licences in the video project's manifest, run the existing pace/mix checks as relevant, and disclose any limitations or failed tests. Do not claim an integration or render has succeeded solely because a binary exists.

## Additional tool workflows

- Use the project-local React packages from `integrations/creative` only when a 3D video needs them. Rapier's physics can be stepped manually at a fixed timestep; reset state or replay from a known initial state for out-of-order frames, and verify repeatable frames before final rendering. Avoid making static-looking visual work depend on physics.
- Postprocessing effects need a working browser/WebGL render and visual QA. Use restrained bloom, grain or depth-of-field when the brief supports it; protect legibility and avoid unrequested effects.
- The isolated audio environment can run the existing onset workflow: `.cache/creative-tools/audio-env/bin/python scripts/audio_tag.py <audio-file> --onsets` on Unix-like systems (use the environment's `Scripts/python.exe` on Windows). Onsets are rough candidates; listen and refine them, and do not treat them as automatic word alignment. PANNs/CLAP models are separate optional requirements.
- To use video-shotcraft, read the cached `.cache/creative-tools/video-shotcraft/SKILL.md` and relevant shot cards as references, subject to current host and user instructions. Choose a specific shot and make it suit the user's brand; do not automatically capture pages, publish, execute upstream scripts, or change agent configurations. The source is not a configured agent skill and the template/workbench dependencies and a full render have not been tested.

## User's visual direction

The user's visual direction, if one exists, lives in the workspace's own draft styles (`.khaam/styles/*.md` inside the workspace, not inside the installed skill). Treat it as an initial proposal to verify, not a locked decision. PixelFX and Blender are optional and are not implied by any reference the user provides.
