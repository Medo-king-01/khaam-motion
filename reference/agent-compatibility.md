# Agent-neutral operation

This is a private compatibility layer for the existing Khaam Motion toolkit. It works with an agent only insofar as that agent can read the files and has the required tools and permissions. There is no universal skill discovery standard: `AGENTS.md` is useful to agents that read it, and other hosts may need the user to attach this folder or explicitly ask the agent to read `SKILL.md` and this guide. Neither file installs an agent integration or gives access to the user's computer.

## Instructions and precedence

For the video workflow use `SKILL.md` and the topic references. Interpret mentions of Claude as the current agent where the action is actually supported. The following agent-neutral rules override Claude-specific onboarding, subscription, model, menus, automatic loading, desktop and access claims in those files. Do not impersonate an application or assert a feature works without checking it. Respect host policies and user instructions.

1. Identify the directory containing `SKILL.md` as `<skill>`. Use absolute paths to its scripts. Do not depend on `CLAUDE_SKILL_DIR`, `@` imports or an agent automatically reading workspace files. `.claude/skills/khaam-motion` remains the existing installer's on-disk location only; it is not a dependency on Claude.
2. Find out what filesystem and shell the host actually exposes. A remote sandbox can work with files uploaded to it, but is not the user's local computer. If a feature or file is unavailable, explain what can and cannot be done and ask for an accessible input or permission when needed. Never promise unattended access to settings or local files.
3. Choose a workspace outside the source skill folder (unless using an already installed copy). Before setting up a workspace, run `python "<skill>/scripts/workspace.py" --plan --preserve-global --path "<workspace>"` and explain the destination and any existing files affected. Ask permission before creating it or copying the skill. Once approved, run `python "<skill>/scripts/workspace.py" --create --install-skill --preserve-global --path "<workspace>"`. Replace placeholders with actual paths, quote paths, and select an available Python interpreter. `--preserve-global` prevents moving a pre-existing global Claude skill. An existing target directory is backed up by the installer even if it is not a valid skill; disclose `target_exists` from the plan. Run the commands only where the user has authorized filesystem access.
4. Run `python "<installed-skill>/scripts/preflight.py"` to inspect dependencies without installing anything. On macOS, follow the safe Apple-stub guidance in `reference/mac.md`. Ask before downloads or installations, and use only tools allowed and accessible in the host environment. HyperFrames requires Node 22+, FFmpeg, and its additional dependencies; readiness must be verified by a smoke test, not inferred from inventory alone.
5. `workspace.py --where` and `--state` are available through the installed copy. For a new video, `workspace.py --new-video "title"` creates its folder. Read `SESSION_HANDOFF.md`, the referenced `PROGRESS.md` and `TASTE.md` and available local taste before continuing. Run project commands from the video's folder, save milestones in the handoff and progress files, and deliver with `--deliver` as documented. Do not assume `@SESSION_HANDOFF.md` is expanded by the host.
6. The key setup's GUI flow may not be supported in a remote or headless host. Never ask the user to put keys in chat, command-line arguments, logs or repository files. If secure secret provisioning is unavailable, skip that integration and use an appropriate free alternative. Get explicit approval before paid requests and save state after them.
7. The agent should do what its tools permit; when opening a file, interacting with a GUI or installing a dependency is impossible, explain the limitation and offer the user the minimum necessary action. No specific vendor model, paid plan or UI is universally required by this toolkit; individual services may have their own requirements.

## Capability levels

- **Read-only agent:** can inspect the instructions and prepare a plan, but cannot install or render.
- **File and shell access:** can set up and render in the accessible environment once dependencies and permissions are in place. Network, browser, GPU, sound and codecs vary by environment.
- **Agent with relevant integrations:** can additionally use explicitly authorized external services, subject to their requirements and cost.

There is no guarantee that every agent will discover these files, support the same tools, or render successfully. Test each target environment with its own permissions and dependency setup.
